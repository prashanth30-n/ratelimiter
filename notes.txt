generally how the bucket based algo works is no matter how many requests it comes from same services it ,the bucket leaks at a constant rate.
but in the ubers implementation uber doesn't literally maintain a bucket
the refilling of bucket is based on elapsed time between requests rather than requiring a discrete interval clock
instead of every 10ms add a token into the bucket ,it effectively maintains a timeline of when request are allowed,The variable State int64 int atomic representation ,it stores a timestamp ,the next schedulted permission time,
atomic operations are on an integer so ,eventhough state stores the next scheduled permission time which should be time.Time type but,as atomic operations are integer type so we are using int64 type for the state,time stamp stored as UnixNano,
